拓展磁盘导致系统无法启动

发表于2026-11-16|更新于2026-11-17|踩坑日常
|浏览量:

背景

Vmware上的Ubuntu空间不足，使用设置拓展磁盘之后，系统无法启动

问题

找不到对应的iso文件

因为我环境已经装好了，所以把之前的iso镜像文件删掉了

后面重新下载回来了

报错如上

AI帮忙解决了，还是AI强

*这是因为你在 VMware 中扩容了虚拟磁盘，但 Linux 系统内部尚未完成分区扩容，或者原磁盘已满（100%）导致图形界面无法启动。* 只要在命令行中完成分区和文件系统的在线扩容（或清理出一点空间），即可恢复正常进入桌面。

请按照以下步骤操作（以最常见的 Ubuntu 系统为例）：

第一步：进入终端并检查磁盘状态

  1. 在报错界面按 Ctrl + Alt + F3（若无反应可试 F2 或 F4）进入命令行终端，输入用户名和密码登录。

  2. 输入以下两个命令查看分区结构与空间使用情况：

    请谨慎使用此类代码。

    • 观察 df -h 中挂载在 / 的分区使用率是否显示为 100%。
  • 观察 lsblk 中磁盘（如 sda 或 nvme0n1）的总容量是否已经变大，但下面的分区（如 sda3 或 ubuntu--vg-ubuntu--lv）容量还没变大。

从截图可以看到：你的磁盘 sda 总容量已经变成 30G，但系统根目录 / 所在的分区 sda2 依然停留在 20G（且没有使用 LVM）。

直接扩展 sda2 分区并刷新文件系统容量即可把新增的 10G 空间合并进根目录。 请按顺序执行以下 4 条命令：

  1. 先清理一点临时空间（防止磁盘 100% 满导致扩容工具报错）

  2. 扩展 sda2 分区大小
    注意 sda 和 2 之间有一个空格： [1]

    (执行成功会提示 CHANGED: partition=2 ...。如果提示找不到 growpart 命令，可先运行 sudo apt update && sudo apt install -y cloud-guest-utils 安装后再执行。)

  3. 扩展文件系统以识别新容量
    这里 sda2 之间没有空格： [1]

  4. 验证容量并重启恢复桌面

确认 / 对应的总容量已变为约 30G（使用率下降）后，执行重启即可正常进入图形界面： [1, 2]
