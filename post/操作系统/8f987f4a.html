linux中的中断相关知识

发表于2026-11-24|更新于2026-11-25|操作系统
|浏览量:

Linux中断（Interrupt）是硬件或软件向CPU发出的异步或同步信号，用于打断CPU当前执行的任务，使其立即转去处理紧急事件。在Linux内核中，中断机制是实现高并发、实时响应和设备驱动管理的核心。以下从硬件基础、Linux中断子系统架构、上下半部机制、内核并发控制及现代演进五个维度进行深度剖析。

中断介绍

中断的底层硬件与分类

从触发源和同步性来看，中断分为两大类：

  1. 硬中断（Hardware Interrupt / Asynchronous Interrupt）
    • 触发源：外部硬件设备（如网卡收到数据包、磁盘完成I/O、时钟芯片定时触发）。
    • 特点：与CPU时钟异步，随时可能发生。
    • 细分：
      • 可屏蔽中断（Maskable IRQ）：通过中断控制器（如APIC、GIC）发送，CPU可通过状态寄存器（如x86的EFLAGS.IF位）选择性忽略。
      • 不可屏蔽中断（NMI）：用于致命硬件错误（如内存校验错误、看门狗超时），CPU必须立即响应。
  2. 软中断 / 异常（Exception / Synchronous Interrupt）
    • 触发源：CPU内部执行指令时产生，与当前指令流同步。
    • 细分：
      • 故障（Fault）：可恢复的异常，如缺页异常（Page Fault）。处理完后重新执行触发异常的指令。
      • 陷阱（Trap）：有意触发的异常，如系统调用（int 0x80或syscall指令）、调试断点（int 3）。处理完后执行下一条指令。
      • 终止（Abort）：不可恢复的严重硬件错误（如Double Fault）。

外设拉高电平/发送MSI消息 → IO-APIC（接收并路由） → Local APIC（每个CPU核心独有，负责仲裁优先级） → CPU核心响应，保存现场并查询 IDT（中断描述符表） → 跳转到内核预设的中断入口函数。

Linux内核中断子系统架构

早期Linux内核直接将硬件IRQ号与处理函数绑定，但面对多核CPU、级联中断控制器和虚拟化时扩展性极差。现代Linux内核引入了IRQ Domain（中断域）和通用中断子系统（GenIRQ）。

核心数据结构

  • irq_desc（中断描述符）：内核为每个逻辑中断号（virq）维护一个struct irq_desc，包含了中断状态、流控处理函数（handle_irq）、以及挂载的驱动处理链表（action）。
  • irqaction：代表具体设备驱动注册的中断处理逻辑。由于多个设备可能共享同一根中断线（Shared IRQ），irq_desc->action是一个单向链表，中断触发时会遍历该链表。
  • irq_chip：抽象了底层硬件中断控制器（如GICv3、APIC）的操作接口，包括屏蔽（irq_mask）、解除屏蔽（irq_unmask）、确认（irq_ack）等。
  • irq_domain：负责将硬件中断控制器内部的本地中断号（hwirq）映射为Linux内核全局统一的虚拟中断号（virq）。

完整生命周期流程

  1. 现场保护（Save Context）：CPU硬件自动压栈部分寄存器（SS, RSP, RFLAGS, CS, RIP），随后内核汇编入口（如arch/x86/entry/entry_64.S）将所有通用寄存器压入当前进程的内核栈（或专用的IRQ Stack，防止内核栈溢出）。
  2. 中断进入与流控：调用irq_enter()更新抢占计数器（preempt_count中的HARDIRQ字段），随后执行generic_handle_irq()，根据中断类型调用电平触发（handle_level_irq）或边沿触发（handle_edge_irq）流控函数。
  3. 执行ISR（中断服务例程）：遍历irq_desc->action链表，依次调用驱动通过request_irq()注册的handler。
  4. 中断退出与调度检查：调用irq_exit()减少HARDIRQ计数。此时内核会检查是否有待处理的软中断（SoftIRQ），若有且不在中断嵌套中，则触发软中断处理。最后恢复寄存器现场，若开启了内核抢占且当前进程被标记了TIF_NEED_RESCHED，则触发进程调度。

核心设计：上半部与下半部（Top Half & Bottom Half）

硬中断执行期间，本地CPU的硬中断通常是关闭的（防止同一中断重入导致栈溢出或死锁）。如果中断处理函数耗时过长，会导致系统丢失其他硬件事件或交互卡顿。因此，Linux将中断处理拆分为两部分：

  • 上半部（Top Half / HardIRQ）：在关中断状态下立即执行。只做最紧急、与硬件直接交互的工作（如读取网卡寄存器状态、清除硬件中断标志、将数据拷贝到内存环形缓冲区），然后登记下半部并迅速退出。
  • 下半部（Bottom Half）：在开中断状态下延迟执行，负责耗时的逻辑（如解析TCP/IP协议栈、将数据交付给用户态进程）。

下半部的三种核心实现机制

机制 执行上下文 能否睡眠 并发特性 典型应用场景
SoftIRQ（软中断） 中断上下文 绝对禁止 静态编译分配；同一类型可在多个CPU上并行执行 网络收发（NET_RX_SOFTIRQ）、块设备I/O、高精度定时器
Tasklet 中断上下文 绝对禁止 基于SoftIRQ实现；同一Tasklet在多核上严格串行 传统字符设备、USB驱动等（现代内核正逐步弃用）
Workqueue（工作队列） 进程上下文（由kworker内核线程执行） 允许睡眠（可调用阻塞API、分配内存） 由内核线程池调度，支持并发与绑定CPU 需要I2C/SPI通信、文件读写、获取互斥锁的复杂硬件处理

补充：Threaded IRQ（线程化中断）
现代内核（尤其是开启PREEMPT_RT实时补丁后）大力推广request_threaded_irq()。它将下半部直接变成一个独立的内核线程（irq/xx-dev），既能享受实时调度优先级，又允许在其中睡眠，大幅降低了系统延迟。

中断上下文与并发控制（核心内核知识）

理解中断就必须理解Linux内核的两种执行上下文及严苛的编程约束：

  1. 中断上下文（Interrupt Context）的铁律
  • 没有关联的进程（current无效）：中断随机打断当前进程，中断处理程序借用被中断进程的内核栈（或独立IRQ栈），但并不代表该进程。
  • 绝对不能睡眠或调度：因为没有独立的task_struct参与调度器队列，一旦在中断上下文调用msleep()、kmalloc(..., GFP_KERNEL)或获取阻塞锁，调度器将无法唤醒它，直接导致内核崩溃（Kernel Panic: scheduling while atomic）。
  • 不可访问用户空间内存：copy_to_user()等函数可能触发缺页异常并导致睡眠，因此严禁在中断中使用。
  • preempt_count（抢占计数器）

每个线程的thread_info中都有一个32位的preempt_count变量，内核通过位掩码精确追踪当前所处的上下文状态：

  • Bits 0–7：抢占禁用计数（preempt_disable()加1）。
  • Bits 8–15：SoftIRQ计数（处于软中断或local_bh_disable()时加1）。
  • Bits 16–19：HardIRQ计数（进入硬中断时加1）。
  • Bit 20：NMI计数。
    内核常用的in_interrupt()、in_irq()、in_softirq()宏，本质上都是通过读取preempt_count的对应位来判断的。
  • 锁与同步原语的选择

当进程上下文与中断上下文共享数据时，必须防止死锁：

  • 错误做法：在进程上下文获取普通自旋锁spin_lock(&lock)。若此时发生硬中断，且中断处理程序也尝试获取同一把lock，由于中断抢占了进程且自旋锁会忙等，CPU将永久死锁。
  • 正确做法：
    • 与硬中断共享数据：进程上下文必须使用 spin_lock_irqsave(&lock, flags)（保存当前中断状态 → 关闭本地CPU硬中断 → 获取自旋锁）。
    • 仅与软中断（SoftIRQ/Tasklet）共享数据：进程上下文使用 spin_lock_bh(&lock)（关闭本地软中断即可，无需关闭硬中断，提升硬件响应能力）。

现代Linux中断优化与高并发演进

在高吞吐量场景（如100Gbps网卡、NVMe SSD阵列）下，传统中断机制会面临**“中断风暴”**（CPU 100%耗费在保存/恢复上下文上，无暇处理业务）。现代内核引入了以下关键技术：

  1. MSI / MSI-X（消息信号中断）
    • 摒弃物理中断引脚，设备直接向指定的内存地址（Local APIC地址）写入特定数据（DMA写操作）来触发中断。
    • MSI-X支持多达2048个独立中断向量，允许现代多队列网卡为每个CPU核心分配专属队列和专属中断，彻底消除多核锁竞争。
  2. NAPI（New API）与中断合并（Interrupt Coalescing）
    • NAPI机制：网卡收到第一个包触发硬中断后，内核立即屏蔽该网卡中断，转入软中断（NET_RX_SOFTIRQ）以**轮询（Polling）**模式批量收包，直到缓冲区清空后再重新开启硬中断。这实现了“低负载用中断（低延迟），高负载用轮询（高吞吐）”的自适应切换。
  3. IRQ Affinity（中断亲和性）
    • 通过/proc/irq/<IRQ_NUM>/smp_affinity文件（或irqbalance守护进程），可将特定设备的中断绑定到指定的CPU核心，配合NUMA架构，确保数据从网卡DMA到内存、再到CPU缓存（L1/L2 Cache）全程在同一个NUMA节点内完成，最大化Cache命中率。

内核中断代码实现

中断注册流转：request_irq()

驱动开发中最常用的 request_irq() 本质是一个内联包装函数，最终核心逻辑在 kernel/irq/manage.c 中。

调用链全景

核心源码拆解（kernel/irq/manage.c）

在 __setup_irq() 内部，内核会做四件关键事情：

  1. 检查共享标志（IRQF_SHARED）：如果 desc->action 链表非空，新旧 action 都必须声明 IRQF_SHARED 且触发方式（边沿/电平）一致，否则返回 -EBUSY。
  2. 创建中断内核线程（若指定了 thread_fn）：调用 kthread_create(irq_thread, ...) 创建名为 irq/<irq>-<name> 的内核线程。
  3. 链表挂载：将新的 action 插入 desc->action 单向链表尾部。
  4. 开启硬件中断线：如果是该中断线的第一个注册者，调用 irq_startup(desc)，最终执行 desc->irq_data.chip->irq_unmask()，在硬件控制器（如 IO-APIC）中解除屏蔽。

硬中断触发流转：从汇编入口到 generic_handle_irq()

在现代 x86_64 内核（5.8+）中，传统的 do_IRQ() 已被重构为基于 DEFINE_IDTENTRY_IRQ 宏生成的架构无关入口（位于 arch/x86/kernel/irq.c）。

硬件与汇编层现场保存

当外设触发中断，CPU 查询 IDT 跳转到汇编桩代码 asm_common_interrupt（由 arch/x86/entry/entry_64.S 生成）：

  1. 压入硬件帧与错误码/向量号：CPU 自动压入 SS, RSP, RFLAGS, CS, RIP，汇编桩压入中断向量号 vector。
  2. 保存通用寄存器：调用 error_entry 宏，将 RDI, RSI, RDX, RCX, RAX, R8-R15 全部压栈，构建出 C 语言可直接读取的 struct pt_regs。
  3. 切换内核态：若中断发生在用户态，执行 swapgs 指令将 GS 寄存器切换为内核的 Per-CPU 基址。

软中断触发与执行：irq_exit() 与 __do_softirq()

当硬中断的上半部执行完毕，代码回到 common_interrupt() 中的 irq_exit_rcu()（定义在 kernel/softirq.c）。这是连接上半部与下半部的桥梁。

触发时机：irq_exit()（kernel/softirq.c）

在 invoke_softirq() 中，如果当前没有强制线程化（force_irqthreads），内核会直接调用 __do_softirq()。

核心执行引擎：__do_softirq()（kernel/softirq.c）

软中断在开硬中断、关软中断的环境下运行，其源码设计极其精妙，核心目标是防止软中断饿死用户态进程：

硬中断中不一定会走到软中断中，可能使用workqueue，threaded irq等机制
硬中断中可以主动抛出软中断以进入下半部的处理流程中，然后在软中断向量表里面触发软中断的处理函数
