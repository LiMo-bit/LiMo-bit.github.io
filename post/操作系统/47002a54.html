块设备驱动

发表于2026-11-14|更新于2026-11-17|操作系统
|浏览量:

总述

块设备是针对存储设备的，比如 SD 卡、EMMC、NAND Flash、Nor Flash、SPI Flash、机
械硬盘、固态硬盘等。因此块设备驱动其实就是这些存储设备驱动，块设备驱动相比字符设备
驱动的主要区别如下：

  • 块设备只能以块为单位进行读写访问，块是 linux 虚拟文件系统(VFS)基本的数据传输
    单位。字符设备是以字节为单位进行数据传输的，不需要缓冲。
  • 块设备在结构上是可以进行随机访问的，对于这些设备的读写都是按块进行的，块设
    备使用缓冲区来暂时存放数据，等到条件成熟以后在一次性将缓冲区中的数据写入块设备中。

块设备使用缓存暂存数据的目的是为了提高块设备寿命，数据先写入到缓冲区中，等满足一定条件后再一次性写入到真正的
物理存储设备中，这样就减少了对块设备的擦除次数，提高了块设备寿命。

块设备I/O请求过程

Linux 块设备 I/O 请求的核心过程是：数据从用户空间经过虚拟文件系统（VFS）与页缓存（Page Cache），被封装为统一的 struct bio 通用块层请求，随后根据驱动类型（传统多队列或现代直通模式）完成合并、调度与物理传输，最后通过中断或 bio_endio() 逐层向上通知完成。

结合你刚刚编写的 my_ramdisk 驱动，整个生命周期可以拆解为以下 5 个核心阶段（自顶向下）：

阶段一：系统调用与页缓存层（VFS & Page Cache）

  1. 发起系统调用：用户进程调用 read()、write() 或 pread()/pwrite()。
  2. 缓冲 I/O 路径（默认）：
    • 内核首先在**页缓存（Page Cache）**中查找目标数据页。
    • 读命中：直接从内存拷贝给用户空间，完全不触发底层块设备驱动。
    • 读未命中 / 写脏页：内核在 Page Cache 分配物理页，并在后台（由 flush 内核线程）或调用 fsync() 时，将脏页向下刷入文件系统层。
  3. 直接 I/O 路径（O_DIRECT，即你测试程序用的方式）：
    • 跳过 Page Cache，内核直接锁住用户空间的内存物理页（Pin Pages），准备直接与块设备交互。

阶段二：文件系统与映射层（Filesystem Layer）

  • 如果操作的是挂载后的文件（如 /mnt/myram/hello.txt），文件系统（如 ext4）会根据文件的 inode 和逻辑块号，查询元数据（Extent 树），将其翻译为磁盘上的物理起始扇区号（Sector）和连续扇区长度。
  • 如果直接操作裸设备（如 /dev/myram0），VFS 的 blkdev 伪文件系统会直接将文件偏移量除以 512 字节，得到对应的磁盘扇区号。

阶段三：通用块层（Generic Block Layer —— struct bio 诞生）

通用块层将所有不同文件系统的读写需求，统一抽象为 struct bio（Block I/O） 结构体（这就是你代码里 myram_submit_bio(struct bio *bio) 收到的核心参数）：

  • 目标地址：bio->bi_iter.bi_sector 记录了要访问的起始扇区号，bi_size 记录总字节数。
  • 数据载体（分散/聚集列表）：由于大块文件在物理内存中往往是不连续的，bio 内部通过 bio_vec 数组指向多个分散的物理内存页片段（page、offset、len），实现单次 I/O 传输多段非连续内存（Scatter-Gather I/O）。
  • 提交请求：上层调用 submit_bio(bio) 将请求正式投递给通用块层。

阶段四：I/O 调度与队列层（blk-mq 多队列 vs 直通模式）

通用块层收到 bio 后，根据底层驱动注册的架构走两条不同路线：

路线 A：现代物理硬件驱动（blk-mq 多队列架构，如 NVMe / SATA SSD）

  1. 请求转换与合并（Merge）：多个相邻扇区的 bio 会被合并成一个更大、连续的 struct request，减少硬件寻址次数。
  2. 软件暂存队列（Software Staging Queues）：每个 CPU 核心拥有独立的软件队列，无锁接收并排序请求（由 I/O 调度器如 mq-deadline、kyber、bfq 控制优先级）。
  3. 硬件派发队列（Hardware Dispatch Queues）：请求被分发到与硬件中断/Ring Buffer 绑定的硬件队列中，驱动的 .queue_rq() 回调被触发，通过 DMA 通知磁盘控制器开始读写数据。

路线 B：无队列直通驱动（submit_bio 模式，即你刚才写的 myram 驱动）

  • 对于内存盘（RAM Disk）、ZRAM、Device Mapper（LVM/RAID）等无机械寻址延迟的虚拟设备，不需要排队合并。
  • submit_bio() 跳过 blk-mq 调度器，直接调用驱动注册的 myram_submit_bio(bio)，在当前上下文中直接完成数据搬运。

阶段五：数据传输与完成回调（Completion）

  1. 执行搬运：
    • 真实硬件：磁盘控制器通过 DMA 在内存与存储介质之间传输数据，完成后触发 硬件中断（IRQ）。
    • 你的 Demo 驱动：遍历 bio_for_each_segment，通过 bvec_kmap_local() 映射物理页，直接用 memcpy() 完成内存拷贝。
  2. 自底向上逐层通知：
    • 驱动调用 bio_endio(bio)（硬件驱动在中断下半部 SoftIRQ 中调用）。
    • 通用块层释放 bio 结构体，并触发 bio->bi_end_io 回调函数。
    • 如果是异步缓冲读写，内核清除页缓存的 Dirty/Writeback 标志；如果是同步或 O_DIRECT 读写，内核唤醒正在休眠等待该 I/O 的用户进程，系统调用返回成功字节数。
