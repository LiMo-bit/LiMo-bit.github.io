进程间通信

发表于2026-11-14|更新于2026-11-15|操作系统
|浏览量:

总述

Linux 进程间通信(IPC, Inter-Process Communication)主要有 6 种核心方式：管道(匿名管道与命名管道)、消息队列、共享内存、信号量、信号以及套接字(Socket)。
可以使用ipcs命令列出linux系统中所有的进程间通信(IPC)设施

6 种进程间通信方式对比

通信方式 适用范围 数据传输特点 优缺点
匿名管道(Pipe) 具有亲缘关系的进程(父子/兄弟) 半双工，字节流，存于内存 简单易用;
仅限亲缘进程，生命周期随着进程结束
为什么只有具有亲缘关系的进程才能使用匿名管道
因为匿名管道是使用的文件描述符进行通信的，所以只有具有亲缘关系的进程才能共享文件描述符，执行了 fork()函数
命名管道(FIFO) 任意本地进程 半双工，字节流，以文件形式存在 打破亲缘限制；
读写可能阻塞，速度较慢
消息队列(Message Queue) 任意本地进程 按消息块(有类型)传输，存于内核 克服管道无格式字节流缺点；
存在内核态/用户态拷贝开销
共享内存(Shared Memory) 任意本地进程 直接读写同一块物理内存 速度最快(零拷贝)；
无内置同步机制，需要配合信号量
信号量(Semaphore) 任意本地进程 不传输数据，仅作为计数器 用于进程同步与互斥；
编程接口较复杂
信号(Signal) 任意本地进程 异步通知机制(软件中断) 开销极小，适合异常处理;
携带信息量极少
套接字(Socket) 本地进程或跨网络不同主机 全双工，支持字节流或者数据报 通用性最强(支持网络)；
本地通信开销略高于共享内存

命名管道(FIFO)

mkfifo 用于创建一个命名管道（FIFO）文件，而 unlink 用于删除文件系统中的一个文件名（链接）并减少其硬链接计数。 在 Linux/Unix 进程间通信（IPC）中，两者常配合使用以创建和清理管道文件。

  1. mkfifo 的功能

mkfifo（Make FIFO）用于在文件系统中创建一个命名管道，使无亲缘关系的进程可以通过读写这个特殊文件进行数据通信。

  • 函数原型：int mkfifo(const char *pathname, mode_t mode);（需包含 <sys/types.h> 和 <sys/stat.h>）
  • 主要参数：
    • pathname：要创建的管道文件路径和名称（如 "/tmp/my_fifo"）。
    • mode：指定管道文件的访问权限（如 0666），实际权限会受当前进程的 umask 影响。
  • 行为特点：
    • 它只会在磁盘目录项中创建一个类型为 p（pipe）的特殊文件节点，管道数据传输完全在内核缓冲区中进行，不会实际占用磁盘数据块。
    • 阻塞特性：默认情况下，以只读方式 open 该管道会阻塞，直到有另一个进程以只写方式打开它（反之亦然）。
  1. unlink 的功能

unlink 用于删除指定路径的目录项（文件名），并使该文件对应的 inode 硬链接计数减 1。

  • 函数原型：int unlink(const char *pathname);（需包含 <unistd.h>）
  • 底层逻辑与行为：
    • 普通文件与管道：如果该文件的硬链接数降为 0，且没有任何进程正在打开该文件，内核会立即释放该文件的 inode 和磁盘空间；如果仍有进程打开着它，目录项会先被删除（外部无法再通过路径找到它），直到最后一个打开它的进程调用 close() 或退出后，内核才真正销毁该文件。
    • 目录限制：unlink 不能用于删除目录（删除空目录需使用 rmdir）。

在 Linux / Unix 系统编程中，#include <fcntl.h> 和 #include <sys/stat.h> 是进行底层文件操作（如 open、stat 等系统调用）时最常包含的两个头文件。它们各自的作用如下： [1, 2]

  1. <fcntl.h> 的作用

  • 名称来源：File Control（文件控制）。

  • 核心功能：定义了与文件控制和打开选项相关的常量、宏定义以及函数声明。 [1]

  • 常见内容：

    • 文件访问模式（传给 open 函数的标志位）：
      • O_RDONLY（只读）
      • O_WRONLY（只写）
      • O_RDWR（读写）
    • 文件创建与控制标志：
      • O_CREAT（若文件不存在则创建）
      • O_EXCL（与 O_CREAT 配合使用，若文件已存在则报错）
      • O_APPEND（追加模式）
      • O_TRUNC（若文件存在且为只写/读写，则清空文件内容）
    • 函数声明：如 open()、creat()、fcntl() 等底层文件操作接口。 [1, 2]

  • <sys/stat.h> 的作用

  • 名称来源：System Statistics（系统状态/属性）。

  • 核心功能：定义了与文件状态、文件属性、权限掩码相关的数据结构和宏定义。 [1]

  • 常见内容：

    • 文件权限模式（Mode）：用于 open 的第三个参数，或者 chmod 等函数，设置文件的访问权限（如 S_IRUSR、S_IWUSR、S_IRWXU 等，类似于八进制权限 0644、0755）。
    • 文件类型宏：用于判断文件类型的宏（如 S_ISREG 判断是否为普通文件，S_ISDIR 判断是否为目录）。
    • stat 结构体：定义了获取文件详细属性的结构体 struct stat（包含文件大小 st_size、inode 编号 st_ino、权限、最后修改时间等），以及 stat()、fstat()、lstat() 等函数的声明。 [1]

共享内存(POSIX Shared Memory)

直接映射物理内存到进程地址空间(编译时需要加-lrt)

*从操作系统底层原理来看，这三步其实是“分工合作”的，并不是* shm_open 一步就拿到了物理内存。

用“租仓库”来类比整个流程，会非常清晰：

  1. shm_open：在内核里“登记一个户口/门牌号”（不占物理内存）
    • 它只是在内核的 tmpfs 文件系统（即 /dev/shm）里创建了一个名为 /my_shm 的虚拟文件节点，并给你发了一张“通行证”（文件描述符 fd）。
    • 此时它还没有分配真正的物理内存，大小为 0 字节。你的理解“获取使用权限”非常贴切——相当于拿到了这间仓库的钥匙和门牌号。
  2. ftruncate：确定“仓库的面积”
    • 告诉内核：“我需要 1024 字节的空间”。（注：由于 Linux 的延迟分配机制，通常要等到真正写入数据时，内核才会按页分配实际的物理内存页框）。
  3. mmap：把仓库直接“打通到你家客厅”（建立映射）
    • 用户态进程是不能直接操作内核物理内存的。mmap 的作用是修改当前进程的页表（Page Table），把你进程里的一个虚拟地址（ptr），直接映射到内核里那块物理内存页上。

信号量(POSIX Semaphore)

维度 信号量(Semapore) 互斥锁(Mutex)
本质 计数器(可为1，也可为N) 二值状态(锁定/未锁定)
用途 既可以用于互斥、也可以用于同步(多线程操作、限流) 专门用于临界区的互斥访问
所有权 无所有权(谁都能up释放) 有所有权(加锁的线程必须是解锁的线程)

本地套接字(Unix Domain Socket)

适用于本地高性能双向通信（无需经过网络协议栈）。

选型建议

  • 父子进程简单传递数据：首选匿名管道
  • 高频、大数据量传输(如音视频帧、高频交易)：首选共享内存 + 信号量
  • 本地多进程双向通信/服务架构(如Docker、MySQL本地连接)：首选Unix Domain Socket。
  • 跨机器通信：必须使用网络Socket(TCP/IP)
