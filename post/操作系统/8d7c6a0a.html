    container_of 宏通过定义一个与目标结构体成员同类型的临时指针 __mptr，利用 C 语言的赋值类型检查规则，在编译期直接拦截类型不匹配的指针传入。

    下面拆解这一行代码的具体工作机制：

    1. 逐层拆解这行“魔法代码”

    重点看第一行：const typeof( ((type *)0)->member ) *__mptr = (ptr);

    • ((type \*)0)->member：把内存地址 0 强制转换成目标结构体 type 的指针，并引用其中的 member 成员。（注意：这里只做了编译期的类型推导，并不会真的去访问 0 地址内存，所以不会触发段错误）。
    • typeof(...)：这是 GCC/Clang 提供的编译器扩展关键字，用来获取表达式的数据类型。这里它精确提取出了结构体 type 中 member 成员的真实类型（例如 struct list_head 或 int）。
    • const <成员类型> \*__mptr = (ptr);：声明了一个临时指针 __mptr，它的类型是指向 member 类型的常量指针，然后直接把外部传入的 ptr 赋值给它。
    • 它是如何拦截错误的？

    在 C 语言中，两个不同类型的指针直接赋值（且没有强制类型转换）是非法的，编译器会立刻发出警告（如 incompatible pointer types）。
