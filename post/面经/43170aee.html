linux应用开发基础

发表于2026-11-22|更新于2026-11-22|面经
|浏览量:

Linux如何调试段错误

display

①GDB定位(bt查看调用栈)→②dmesg查看内核崩溃信息→③开启core dump(ulimit -c unlimited)→④GDB分析core文件→⑤ASAN编译检测。段错误通常是空指针或越界。

常见段错误原因：

  • 空指针解引用
  • 数组越界
  • 已释放内存再访问(use-after-free)
  • 栈溢出(递归太深/局部大数组)

strace和ltrace的用法？

display

strace跟踪系统调用(如open/read/write/ioctl的参数和返回值)。ltrace跟踪动态库函数调用。嵌入式中strace -e trace=open定位文件访问问题特别有用。

/proc文件系统在调试中的应用

display

/proc/PID/maps(内存映射)、/proc/PID/status(进程状态)、/proc/PID/fd(打开的文件描述符)、/proc/meminfo(系统内存)。不需要额外工具就能获取丰富的调试信息。

什么是交叉编译？嵌入式开发为什么需要？

display

交叉编译是在PC(x86)上编译能在目标板(ARM)运行的程序。因为目标板资源有限跑不了编译器。工具链如arm-linux-gnueabihf-gcc。嵌入式开发的必备技能。

GDB远程调试的方法

display

目标板运行gdbserver监听端口→PC的GDB用target remote ip

连接→即可远程设断点、单步、查看变量。嵌入式Linux调试的标准方法。

open的flag

display

open的flags：

  • O_RDONLY/O_WRONLY/O_RDWR: 访问模式
  • O_CREAT: 不存在则创建
  • O_TRUNC: 存在则清空
  • O_APPEND: 追加写
  • O_NONBLOCK: 非阻塞

标准IO(fopen/fread)和系统IO(open/read)的区别？

display

linux中的标准I/O是指ANSI C 标准在 <stdio.h> 中定义的一组面向流的输入/输出库函数，它构建在底层文件 I/O 系统调用之上。

标准IO(fopen/fread)带用户态缓冲区(减少系统调用次数)，系统IO(open/read)直接调用内核。标准IO效率更高(批量I/O)，系统IO控制更精细(无缓冲延迟)。

文件描述符的复制

display

dup(oldfd)复制fd到最小可用fd号，dup2(oldfd, newfd)复制到指定fd号。经典用法：dup2(pipefd, STDOUT_FILENO)实现重定向——printf的输出就走管道了。

fcntl和ioctl的区别？

display

fcntl操作文件描述符属性(设置非阻塞、文件锁等)。ioctl操作设备(设置串口波特率、控制外设等)。fcntl是通用文件操作，ioctl是设备特定控制——记住这个区别。

mmap内存映射文件的使用？

display

mmap将文件映射到进程地址空间→普通的指针读写等于文件IO→munmap解除映射。零拷贝、高效。嵌入式中mmap常用于访问设备寄存器(/dev/mem)和进程间共享内存。

mmap vs read/write：

  • mmap优势：大文件随机访问、零拷贝(内核与用户态共享物理页)
  • read优势：顺序小文件、代码简单

select/poll/epoll的使用场景

display

select适合少量fd(≤1024)的简单场景。poll去掉了fd数量限制但仍需遍历。epoll基于事件驱动(O(1))适合大量连接。嵌入式Linux网络服务用epoll是标准实践。

文件锁(flock/fcntl锁)的使用？

display

flock整文件加锁(简单)，fcntl锁可以锁文件的某段区域(字节范围锁)。文件锁用于多进程访问同一个文件时的同步。嵌入式配置文件修改、日志写入等场景会用到。

inotify文件系统事件监控

display

inotify监控文件/目录的创建、删除、修改、移动等事件。inotify_init→inotify_add_watch→read事件。嵌入式中用于监控配置文件变化或热插拔设备节点。

Linux下大文件的处理方法？

display

大文件处理：mmap分段映射、使用O_LARGEFILE标志、fseeko支持64位偏移、sendfile零拷贝传输。编译时定义_FILE_OFFSET_BITS=64启用大文件支持。

/dev/null和/dev/zero的作用？

display

/dev/null是黑洞(写入的数据全丢弃)，用于丢弃不需要的输出。/dev/zero是零源(读出的全是0)，用于初始化内存或创建空文件。嵌入式测试中经常用到。

异步IO(aio)的使用

display

aio_read/aio_write发起异步IO→继续干其他事→aio_return/aio_error检查完成状态。或用io_uring(新一代异步IO，更高效)。适合高性能I/O密集场景。

目录操作(opendir/readdir)

display

opendir打开目录→readdir逐个读取目录项(返回struct dirent含文件名和类型)→closedir关闭。配合stat获取文件详细信息。遍历目录树用递归。

stat系列函数获取文件信息

display

stat(path)/fstat(fd)/lstat(path,不跟软链接)获取文件的大小、权限、修改时间、inode号、文件类型等信息。struct stat中st_mode判断是文件/目录/设备。

文件系统空间查询(statfs)

display

statfs/fstatfs获取文件系统信息：总空间、可用空间、块大小、inode数量。嵌入式中用于监控Flash/SD卡剩余空间，防止日志写满文件系统。

tmpfile和mkstemp临时文件

display

tmpfile()创建匿名临时文件(自动删除)。mkstemp()创建有名临时文件(需手动unlink)。临时文件用于中间结果存储，避免程序崩溃后留下垃圾文件。

fork创建子进程的典型用法

display

fork后父子进程通过返回值区分→子进程exec加载新程序或执行任务→父进程wait回收子进程。典型场景：Shell执行命令、守护进程、多进程服务器。

wait/waitpid的作用和区别？

display

wait阻塞等待任意子进程结束，waitpid可以指定等某个子进程且支持非阻塞(WNOHANG)。回收子进程防止变成僵尸进程。WIFSIGNALED等宏检查退出原因。

如何创建守护jinchng

display

创建守护进程步骤：fork→父进程退出→setsid创建新会话→再fork→关闭所有fd→重定向stdin/stdout/stderr到/dev/null→chdir到/→写PID文件。

进程组和会话的概念

display

进程组是一组相关进程(如管道命令组)，会话是一组进程组(对应一个终端)。Ctrl+C发信号给前台进程组。守护进程通过setsid脱离终端会话。

exec族函数(execl/execv/execve)

display

exec族函数用新程序替换当前进程映像(PID不变)。l(列表参数)/v(数组参数)、p(搜索PATH)、e(指定环境变量)的组合。fork+exec是创建新进程的标准模式。

exec后PID不变，但以下继承：

  • 文件描述符(除非设置FD_CLOEXEC)
  • 进程ID、父进程ID
  • 信号掩码

system()和popen()的使用？

display

system()执行Shell命令(创建子进程+Shell解析+等待完成)。popen()执行命令并通过管道读写其输入输出。popen更灵活，system更简单。注意：两者都有Shell注入风险。

进程间通信之管道(pipe)

display

pipe()创建匿名管道→fork→父进程关读端写数据→子进程关写端读数据。管道是半双工的——要双向通信需要创建两个管道。最基本的IPC。

命名管道(FIFO)的使用

display

FIFO是有名字的管道(在文件系统中可见)——无亲缘关系的进程也能通信。mkfifo创建→一个进程open写→另一个open读。常用于简单的进程间数据传递。

共享内存(POSIX接口)

display

shm_open创建共享内存对象→ftruncate设置大小→mmap映射到进程→读写→munmap→shm_unlink。是最快的IPC方式——直接操作同一块物理内存。需要配合同步机制。

消息队列(POSIX接口)

display

mq_open创建消息队列→mq_send发消息→mq_receive收消息→mq_close→mq_unlink。消息队列自带同步(空时收阻塞、满时发阻塞)，比管道支持消息优先级。

信号的处理方法

display

signal()/sigaction()注册信号处理函数。sigaction更强大(可获取信号信息、控制行为)。信号处理函数中只能调用异步信号安全函数(不能用printf/malloc)。

信号量(POSIX有名/无名信号量)

display

有名信号量(sem_open，跨进程)和无名信号量(sem_init，线程间或共享内存)。sem_wait减1(为0阻塞)→sem_post加1(唤醒等待者)。用于控制资源访问和同步。

多进程并发服务器模型

display

主进程listen→accept后fork子进程处理连接→父进程继续accept→子进程处理完exit。简单直观但每连接一个进程开销大。改进：预fork进程池或改用多线程/epoll。

进程资源限制(setrlimit)

display

setrlimit设置进程资源限制：最大文件数(RLIMIT_NOFILE)、最大栈大小(RLIMIT_STACK)、最大CPU时间。嵌入式中用于限制进程资源使用防止资源耗尽。

进程优先级设置(nice/setpriority)

display

nice值(-20到19)调整进程优先级：值越低优先级越高。实时进程用sched_setscheduler设置SCHED_FIFO/RR。嵌入式中关键任务设高优先级保证实时性。
